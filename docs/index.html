Workflow

Before and after

Same six-point deliverable as today: description, deviation, professional assessment, solution, assumptions, documentation. But each step is data that can be checked and reused.

Today

  1. Free-text formCustomer describes the task, attaches drawings.
  2. Follow-upAdviser calls for missing sizes and brands.
  3. PDF lookupTested set-ups found by hand, system by system.
  4. WordArgument written from scratch; precedents from memory.
  5. PDF sentNo link to the project, revisions or execution.

With Gennemført 2.0

  1. Structured enquiryFields per penetration, photo checklist, live pre-check.
  2. TriageTested set-ups answered at once; the rest routed east/west.
  3. Case + precedentNearest ETA row, deviation signature, earlier decisions.
  4. Decision + four eyesAdviser's own argument; reviewed by a colleague; hash-chained.
  5. Verifiable issuePDF with ETA excerpt, QR code, site checklist, owner package.

Verification

Nothing has to be taken on trust

Every output has a check a person can do in minutes, and an automated one that runs on every change.

1The file

Every deliverable is in a SHA-256 manifest with the step, model, knowledge base and code that produced it. Drag a file onto Verificér; it is hashed in your browser, never uploaded.

2The answer

Every verdict shows the ETA page with the tested row highlighted, a link to the official PDF at that page, and each parameter as designed vs tested.

3The method

python -m gennemfoert.reproduce rebuilds everything from the source model and compares it with what is published: 9/9 checks.
